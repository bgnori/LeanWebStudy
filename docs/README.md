# ドキュメントの入口

本リポジトリには、目的の違う二つの取り組みがある。まず読む側を選ぶ。

| 取り組み | 問い | 入口 |
|---|---|---|
| Web ApplicationのStudy | Leanでアプリをどう書き、既存ライブラリをどう組み合わせるか | [アプリStudy](./application-study/README.md) |
| Std拡張WebSocketの開発（移転済み） | 実装・文書は[bgnori/same-port-websocket](https://github.com/bgnori/same-port-websocket)へ移転。本リポジトリは利用側 | [移転案内](./std-websocket/README.md) |

## 派生の関係

```text
アプリStudy: チャット・Pong等でWebSocketを使う
  → 既存構成では別リスナー、接続移譲、運用の負担が大きいと分かった
  → 派生研究: Std拡張として自然なWebSocketを試作する
  → 成功すれば独立プロジェクト化し、Lean本家へのPRを目指す
```

アプリStudyを進めるために、WebSocketの設計・証明の全資料を読む必要はない。
逆に、WebSocket側の検証成功は、Studyアプリ全体の実用性・本番品質の保証ではない。
独立化・本家へのPRは将来の方向であり、実施済み・採用見込みという意味ではない。

## 読み方と更新先

- 起動・利用は[ルートREADME](../README.md)。
- 各トラックの入口は目的・現状・読む順序を短く保つ。
- 詳細な根拠や過去の比較は各トラックの専門文書へ置く。
- 二つをまたぐ内容は、アプリ側には利用上の結果、開発側にはAPI・契約上の課題を書く。
  根拠を丸ごと複製せず相互リンクする。

今回は文書だけを分離した。ソース、Lakeパッケージ、テスト実行単位はまだ同じである。
