# プロジェクト用語集

この文書は、README やサンプルページ、実装を読むときに出てくる語彙を整理したものです。
各語の分類は、次の意味で使っています。

- **一般技術用語**：Web 開発やソフトウェア開発で広く使われる語。
- **Lean エコシステム用語**：Lean 4、Lake、または Lean 向けライブラリーの文脈で使われる語。
- **プロジェクト固有用語**：このリポジトリ内の構成、実装、サンプル機能を指す語。この文書での定義は他のプロジェクトにそのまま当てはまるとは限りません。

分類は語の使われる文脈を示すもので、専門用語の厳密な境界を示すものではありません。
特にライブラリー名は Lean 向けであっても、Lean 言語そのものの標準用語とは限りません。

## Web・ソフトウェア開発で一般的な用語

| 用語 | 意味と、このプロジェクトでの使われ方 |
| --- | --- |
| **HTTP リクエスト / レスポンス** | クライアントからサーバーへの要求と、その返答。ページ取得には主に `GET`、投稿や更新には `POST` を使います。 |
| **ルート / エンドポイント** | URL と HTTP メソッドに対応する処理先。たとえば `GET /health` はヘルスチェック、`POST /board/` は掲示板への投稿です。動的ページの URL は `Pages/` 内の Lean ファイルに対応します。 |
| **ハンドラー (handler)** | リクエストを受け取り、処理してレスポンスを返すコード。本プロジェクトの `WebHandler` はデータベース、ページ、ルーターなどをまとめて扱います。 |
| **ステータスコード** | HTTP レスポンスの結果を表す番号。成功には `200`、ページがない場合には `404`、未対応メソッドには `405`、内部エラーには `500` を使います。 |
| **JSON** | 構造化データを表すテキスト形式。サーバーからページ worker への `Page.Context` の受け渡しや、API・チャットメッセージに使います。 |
| **HTML エスケープ** | 文字列を HTML の構文として解釈されない形に変換すること。利用者が入力した文章などを安全に表示するために使います。 |
| **SQL / パラメーター化クエリー** | SQL はリレーショナルデータベースを操作する言語です。パラメーター化クエリーでは、SQL 文と値を分けて渡します。本プロジェクトでは MapleSQL が文とパラメーターを作り、SQLite が実行します。 |
| **スキーマ (schema)** | データの構造や制約の定義。ここでは SQLite のテーブル定義などを指します。画面に表示する「元 JSON のスキーマ」はデータ項目の説明であり、JSON Schema 形式とは限りません。 |
| **インメモリデータベース** | 主にメモリー上に存在し、通常はプロセス終了後に保持されないデータベース。本プロジェクトの SQLite はサーバー起動時に `:memory:` で作成するため、再起動すると掲示板・Wiki のデータが消えます。 |
| **WebSocket** | 接続を維持し、クライアントとサーバーが双方向にメッセージを送る通信方式。本プロジェクトではリアルタイムチャットと Pong に使用します。 |
| **HTTP Upgrade** | HTTP 接続を別のプロトコルへ切り替える仕組み。WebSocket 接続の開始にも使われます。本プロジェクトでは通常のページ取得と WebSocket 通信を区別して扱います。 |
| **SSE (Server-Sent Events)** | HTTP 接続を使い、サーバーからブラウザーへイベントを逐次送る仕組み。WebSocket と異なり一方向配信なので、本プロジェクトの SSE チャットでは投稿を別の `POST` で送ります。 |
| **ポーリング (polling)** | クライアントが一定間隔でサーバーに問い合わせる方式。チャットの送受信には使いません。開発プレビューの状態確認には別途ポーリングを使います。 |
| **mutex (ミューテックス)** | 同時に実行される処理が共有状態を安全に扱うための排他制御。本プロジェクトではデータベースやカウンターなどの共有状態を保護します。 |
| **loopback (ループバック)** | 同じコンピューター内からのみ接続できるネットワーク範囲。アプリケーションと開発プレビューはローカル利用を前提に loopback にバインドします。 |
| **FFI (Foreign Function Interface)** | 異なる言語で書かれたコードを接続する仕組み。Lean から SQLite や libwebsockets のネイティブ C コードを呼び出す箇所で使います。 |

## Lean 4・Lean エコシステムの用語

| 用語 | 意味と、このプロジェクトでの使われ方 |
| --- | --- |
| **Lean 4** | 定理証明支援系であり、関数型プログラミング言語でもある処理系。本プロジェクトではサーバー、ページ、データ処理を実装します。 |
| **定理証明支援系 (proof assistant)** | 定理やプログラムの性質を形式的に記述し、証明を検査するソフトウェア。Lean はこの用途を持ちますが、本プロジェクト自体は主に Web アプリ開発の学習用です。 |
| **Lake** | Lean のビルド・パッケージ管理ツール。`lake build` はビルド、`lake test` はテスト、`lake exe leanwebstudy` は実行ファイルの起動に使います。 |
| **toolchain (ツールチェーン)** | プロジェクトで使うコンパイラーや関連ツールのバージョン一式。ルートの `lean-toolchain` が Lean 4.35.0 を指定します。 |
| **モジュール / `import`** | Lean のソースファイルを単位として名前や定義を分け、`import` で他のモジュールを利用します。ページ worker も Lean ソースですが、ビルド済みの import 先を利用します。 |
| **`.olean`** | Lean のビルドで生成されるコンパイル済みモジュール成果物。worker が import する helper の変更は、そのモジュールをビルドしないと反映されないことがあります。 |
| **型検査 (type checking)** | プログラムが Lean の型規則を満たすか確認すること。ページのチェックは型検査であり、ページの `main` を実行することとは別です。 |
| **`IO`** | ファイル、プロセス、ネットワークなどの外部作用を行う Lean の計算を表す型。本プロジェクトのサーバーやページの `main` は `IO` を使います。 |
| **DSL (Domain-Specific Language)** | 特定領域の記述を簡潔にするための言語・API。`lean-html` は Lean 内で型付き HTML 要素を組み立てる DSL です。 |
| **lean-html** | Lean で HTML を組み立てる依存ライブラリー。HTML テンプレートファイルを別に処理する方式ではなく、Lean コードから要素を作ります。 |
| **Lithe** | Lean 向けの HTTP ルーティング／ディスパッチ用ライブラリー。本プロジェクトではルート登録とリクエストの振り分けに使います。 |
| **MapleSQL** | Lean 向けの SQL 文生成ライブラリー。本プロジェクトでは `Statement` から SQL と値パラメーターを生成します。DB 接続や SQL の実行自体は担当しません。 |

## このプロジェクト内での用語

| 用語 | この文書で指すもの |
| --- | --- |
| **ページ (`Pages/`)** | URL に対応する Lean ソースファイル。たとえば `/sqlite/users` は `Pages/sqlite/users.lean` に対応します。URL の末尾がディレクトリーを表す場合は `index.lean` を使います。 |
| **ページ fallback** | `/health` などの明示ルートに一致しないリクエストを、動的ページとして探す経路。ページごとに Lithe へルート登録する必要はありません。 |
| **ページ worker** | リクエストごとに起動する `lake env lean --run <ページソース>` の別プロセス。サーバーから JSON の `Page.Context` を受け取り、HTML を JSON 文字列として返します。 |
| **`Page.Context`** | サーバーがページ worker に渡す JSON データの契約。リクエスト番号、パス、SQLite の表示用 HTML、掲示板投稿、Wiki 記事などを含みます。worker はサーバーの DB 接続を直接共有しません。 |
| **ページの再読み込み** | ブラウザーの要求ごとにページソースを別プロセスで実行し直すこと。ページ本体の編集はサーバー再起動なしで反映されますが、import 先のビルド済みモジュールやサーバー側実装の変更まで自動反映するものではありません。 |
| **開発 watcher (`tools/dev.py`)** | ソース変更を監視してビルド、ページ検査、バックエンド再起動、プレビュー更新を行う開発用 Python プログラム。アプリケーションの本番向け機能ではありません。 |
| **プレビュー / プレビュー proxy** | watcher が提供する loopback 限定の開発用入口。バックエンドの再起動中も URL を維持し、状態表示や WebSocket トンネルを提供します。通常の `lake exe leanwebstudy` とは別の開発用経路です。 |
| **バックエンド** | watcher から起動・再起動される Lean の Web サーバープロセス。再起動時にはインメモリ DB、リクエストカウンター、メモリー上のチャット履歴も作り直されます。 |
| **更新境界** | 変更内容ごとに、ページ再読み込みだけでよいか、モジュールのビルドやサーバー再起動が必要かの違い。`Pages/**/*.lean` の変更と `LeanWebStudy.lean`・DB fixture の変更では必要な操作が異なります。 |
| **`/chat/` と `/chat-sse/`** | 同じチャット機能の二つのサンプル経路。前者は WebSocket、後者は SSE で受信し HTTP `POST` で投稿します。SSE 版は最新 50 件をメモリー上に保持し、サーバー再起動で消去します。 |
| **WebSocket ポート / トンネル** | チャットと Pong 用に同じプロセス内で開く loopback 限定の一時ポートと、開発プレビュー経由の中継経路。通常の HTTP ポートとは役割が異なります。 |
| **`requestId`** | 文脈によって役割が異なる識別子。ページコンテキストではサーバーが採番する要求番号、チャットでは投稿の重複表示を避けるためクライアントが送る ID です。単一の全体 ID として扱わないでください。 |
